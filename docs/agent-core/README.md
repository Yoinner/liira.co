# Núcleo conversacional · contrato y estado

## Separación reutilizable

`lib/agent-core/` contiene el adaptador de AI Gateway, validación de resultados, transcript y límites generales. `lib/whatsapp/amanda-business.ts` y `amanda-tools.ts` aportan identidad, datos y herramientas de lectura de Liira. Canal, base, secretos y conocimiento de clientes siguen aislados por negocio; esta separación no hace al repositorio multiempresa.

Para otro negocio se requiere un perfil propio, fuentes de conocimiento y herramientas autorizadas, una base aislada, pruebas con sus conversaciones y aprobación de sus políticas. No se reutilizan clientes, orientaciones, mensajes ni credenciales de Liira.

## Flujo implementado

Webhook firmado → persistencia idempotente por `provider_message_id` (RPC transaccional pendiente de staging) → `agent_due_at` a tres segundos → reclamación por conversación → contexto de hasta 40 mensajes y memoria de trabajo → generación estructurada con hasta cuatro rondas de herramientas de solo lectura → comprobación de modo y último mensaje → envío oficial. Las herramientas consultan catálogo, detalle y disponibilidad, políticas y pendientes; no pueden cobrar, alterar inventario ni enviar mensajes. El cron recupera hasta cuatro conversaciones vencidas por minuto. Una ejecución que llegó a `sending` no se reenvía automáticamente si falla: el resultado ante Meta podría ser incierto. El cupo global de AI Gateway se reserva en Postgres antes de **cada ronda**, incluso entre instancias serverless; los excesos vuelven a la cola persistente con reintento acotado.

Las orientaciones resueltas se consultan solo dentro de la misma conversación. Una solicitud de Daniela no cambia `autonomous`; solo la toma manual desde el panel lo hace. Su respuesta se vincula al caso por código, referencia al mensaje o identificación inequívoca, y el modelo la reevalúa con el historial actualizado. Una ventana cerrada o el modo humano impiden el envío automático. Si AI Gateway falla, Amanda no fabrica una respuesta ni escala por defecto: registra una incidencia y reintenta con límite cuando es seguro.

`agent_context` guarda un resumen de trabajo que el modelo propone; el historial de mensajes sigue siendo la fuente original. La lectura asistida expone estado real (`pending`, `processing`, `completed`, `error`) y se puede recalcular sin enviar un mensaje. No se muestra una confianza porcentual sin calibración. Los estados financieros y ventas cerradas requieren evidencia externa o corrección humana; una cotización de envío nunca es una venta.

## Límites actuales y liberación

- `20261017010000_amanda_conversation_queue.sql` se aplicó manualmente en Supabase Production durante la fase anterior, aunque no figura en el historial de migraciones. `20261017020000_amanda_retry_attempts.sql`, `20261017030000_amanda_gateway_budget.sql` y `20261017040000_amanda_manual_commerce.sql` **no** se han aplicado en Production. Las diez migraciones sí aplicaron y las tres nuevas se reejecutaron en Supabase local aislado con datos ficticios; falta un Preview alojado aislado y pruebas de la aplicación contra él. Desplegar este código sin la migración productiva dejaría webhooks, cola o pagos manuales inoperantes.
- No existe respuesta prefabricada cuando falla AI Gateway. La incidencia queda visible para tratamiento técnico u operativo.
- El envío de Meta no aporta una clave de idempotencia de aplicación: la fase `sending` bloquea reintentos automáticos inciertos. Mission Control muestra ejecuciones fallidas para revisión.
- Las alertas fuera de 24 horas ya no reutilizan la plantilla comercial del cliente: quedan en cola hasta configurar `WHATSAPP_OPERATOR_TEMPLATE_NAME` con una plantilla interna aprobada por Meta. `alerta_interna_amanda_liira` seguía **En revisión** en Meta el 18/10/2026; aceptación de la API no prueba entrega. Dentro de ventana se envía el detalle libre. Si el resultado del envío es incierto, no se reintenta ciegamente.
- Imágenes y videos se almacenan y revisan por Daniela; no se realiza análisis visual automático ni verificación de comprobantes por IA.
- La memoria de trabajo es sugerida por el modelo. Una orientación solo se vuelve regla general si una persona redacta y aprueba expresamente el procedimiento en el panel; queda ligada al caso, auditada, versionada desde la primera versión y puede revocarse. No se promueve automáticamente ni se comparte con otros negocios. Todavía falta un flujo editorial para editar versiones posteriores de una regla.
- No existe pasarela de pago, validación bancaria automática ni integración con transportadora. El módulo manual propuesto exige que una administradora apruebe titularidad/divulgación del medio, importe, pedido y —para enlaces— un host de proveedor en `AMANDA_PAYMENT_LINK_HOSTS`. Un comprobante solo abre revisión; la confirmación requiere verificar fondos en la cuenta receptora y registrar una referencia única en el panel. Estos controles **no** están operativos hasta probar/aplicar la migración. La cotización de envío ahora tiene entidad vinculada a caso, conversación, pedido opcional, destino, importe y vencimiento; Amanda comprueba que el último mensaje y pedido sigan siendo los aprobados antes de enviarla. Un cambio posterior exige nueva revisión.
- Con `AMANDA_ENABLED=true`, el valor predeterminado del despliegue es `AMANDA_ROLLOUT_MODE=pilot`: solo atiende números de `AMANDA_TEST_PHONE_ALLOWLIST` (formato colombiano de 10 o 12 dígitos). Una lista vacía no autoriza a ningún cliente. El modo `all` requiere decisión explícita posterior. Las alertas privadas con resultado incierto no se reenvían solas; el panel permite rearmarlas solo tras revisar el chat y registra la acción.
- El valor predeterminado local es `google/gemini-2.5-flash`. El 18/10/2026 respondió desde `lib/agent-core/gateway.ts` a una solicitud de prueba con herramienta ficticia: HTTP 200, llamada real a `searchProducts`, JSON validado por Zod, 339 tokens de entrada y 515 de salida en tres rondas, aproximadamente 7 s y US$0,0014 según los logs. Una clave temporal limitada a US$1 se revocó al terminar. El código usa HTTP compatible directo; **no** tiene instalado Vercel AI SDK. `AI_GATEWAY_MODEL` prevalece sobre el predeterminado: en el panel de Vercel, **Production todavía seleccionaba `openai/gpt-6-luna`** (403 `RestrictedModelsError`); no se cambió. No había otra variable `AI_GATEWAY_MODEL` listada para Preview/Development.
- El catálogo público verificado el 18/10/2026 mostraba tres categorías y **0 piezas activas**; el agente no puede ofrecer existencias específicas hasta que la dueña publique productos. Este resultado demuestra lectura de la web, no acceso directo al estado interno de Supabase.
- Antes de producción: los SQL y la concurrencia ya pasaron en Supabase local; verificar en una función desplegada con base aislada el modelo/credencial y completar prueba integral de WhatsApp con números de prueba, plantilla interna aprobada, pagos y envíos manuales; comprobar reversión. No se hizo push ni despliegue.

## Regla de adaptación

El modelo conversa y propone; el backend valida ventanas de WhatsApp, modo humano, actualidad del contexto, formato, idempotencia y acciones permitidas. Toda empresa aporta identidad, tono, catálogo o servicios, políticas, responsables, datos aislados y pruebas propias. No reutilizar textos comerciales ni datos de clientes de este proyecto.
